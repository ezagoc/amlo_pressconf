# Tiempo source-missing classification and controlled recovery

Author: Kevin. Scope: the already frozen Tiempo queue only.

This successor changes the **stop classification policy**. It is not a claim that
all stop rules are unchanged. It replaces repeated URL-specific exceptions with
a strict, versioned feature decision for the observed empty static article
template. It does not repair or invent unavailable article text.

The investigated responses have coherent article identity, titles and publication
evidence, but empty lead/body containers and empty structured article text.
Generic video CSS and an initializer without a media target do not prove video.
Earlier actual source readings remain evidence; they do not complete the next
400-row actual AI gate.

Only responses satisfying the full classifier can be explained as source-missing:
complete, correctly bound successful HTML transport; the recognized article
template; consistent request/final/canonical and title evidence; consistent
article publication evidence; empty article text across independent channels;
and no unaccounted prose, media, structure or dynamic-content indicator. Inspected
site boilerplate has narrow structural/script fingerprints. A new target URL is
not itself an exception. Empty text, HTTP 200 or a similar headline alone is
insufficient.

Matched pages receive a separately saved source-unavailable classification, with
the rule version and source/result/check bindings. Their original null text,
failure code, automatic checks, request history and not_reviewed state remain.
They are not successful articles, confirmed video pages or human-approved data.
The classification describes the saved response; it does not establish permanent
historical loss or the absence of content in an earlier website version.

All original rolling risk history remains available. Only positively explained
source-body gaps are excluded from the operational unexplained-anomaly count.
Actual prose omissions, wrong identity, access failures, incomplete responses,
unknown page/media/dynamic structures and unexplained missing-body cases still
stop. Existing verified short/video retention, service limits, spacing, retries,
disk reserve and actual AI gates remain in force.

Offline recovery must verify existing donor files before creating any recovery
export. Use a disjoint successor, preserving the donor's 336 saved results and
closed calls exactly once, its halt, prior recovery lineage and pending duties.
Original child65 position337 is the first new request. Another64 requests reach
400 and complete the existing 80-row batch. Save/readback verification and the
real 400-row AI gate must precede position401. No investigation note substitutes
for this gate.

The initial feature policy stopped at position335 because four changing sidebar
poll percentages did not match static comment fingerprints. The saved article
still had no body or article-specific media. The revised rule permits only the
inspected percentage-comment syntax in verified sidebar poll progress bars,
with numeric range and agreement with the bar attributes and visible label.
It does not permit arbitrary numeric comments, article comments, prose or embeds.
The old rule, rejected classification and technical stop remain unchanged.
The successor verifies that earlier classification under its original frozen
code, then saves separate decisions under the revised rule. This correction is
not an additional URL whitelist or a new source-reading approval.

Use the recorded successor locator and fixed code version, not an older stopped
directory. A prepared namespace is not proof of live collection. Check the actual
collector, battery guard and source-reader tasks. Keep reviewer drafts outside
receipts and publish only through the validated atomic publisher.

At closeout, reconcile the original queue without adding inherited copies or the
fixed 2670 package. Separate successful candidates, usable source-field gaps,
source-unavailable responses and failures. Queue completion is not newspaper
coverage completion, unique-article counting or Joaquin's acceptance.

The next preserved stop at position336 was caused solely by repeated whitespace
in an otherwise identical JSON-LD author name. The classifier now compares that
name with the native normalized name using whitespace collapse only. It still
requires the exact author object keys/type, identical name tokens and case, and
all entity, article, transport and content checks. Original names and failed
results are unchanged. This is not author inference, a person whitelist or
permission to ignore different names. The successor preserves the336-result
donor and its original rejected decision, verifies it under its own frozen code,
and starts at337 only after formal offline preparation and independent review.
